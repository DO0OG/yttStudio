# 프리뷰 뷰포트 모드 실측 기록

> **문서 기준:** v0.3.0 (2026-09-01)

프리뷰가 유튜브 플레이어의 모드별 자막 배치를 재현하려면 각 모드의 기하를 알아야 한다.
이 문서는 실제 플레이어를 측정한 값과 그로부터 끌어낸 규칙을 남긴다.

## 측정 방법

- 대상: `https://www.youtube.com/watch?v=jNQXAC9IVRw` (영어 자막 트랙)
- 도구: 브라우저에서 `getBoundingClientRect()` 와 `getComputedStyle()` 직접 조회
- 측정 항목: 플레이어 영역, 자막 컨테이너(`.ytp-caption-window-container`),
  자막 창(`.caption-window`), 자막 글자 크기(`.ytp-caption-segment` 의 `font-size`)
- 플레이어 크기 변경 직후에는 값이 안정화되기 전이라 오염된다. 전환 뒤 다시 읽어 확인했다.

## 측정값

| 모드 | 플레이어 | 자막 글자 | 글자 ÷ 너비 | 자막 컨테이너 |
|---|---|---|---|---|
| 일반 | 794 × 437.5 | 19.4456 px | 0.0244907 | 0,0 → 794 × 437.5 (플레이어 전체) |
| 극장 | 1162 × 634 | 28.4582 px | 0.0244907 | 플레이어 전체 |

자막 창은 두 모드 모두 `bottom: 2%` 로 배치되었다. 좌우 위치와 너비는 자막 내용에 따라
달라지므로 기하 상수로 쓰지 않는다.

## 끌어낸 규칙

### 1. 자막 컨테이너는 플레이어 전체다

두 모드 모두 자막 컨테이너가 플레이어 영역과 정확히 같았다. 자막 창은 이 컨테이너 안에서
백분율로 배치된다. 즉 `SubtitleSpace` 는 플레이어 영역과 같고, 세이프 에어리어 여백은
백분율 인셋(측정된 하단 값 2%)으로 표현된다.

### 2. 글자 크기는 플레이어 **너비**에 비례한다

```
글자 크기 = 플레이어 너비 × 0.0244907
```

두 측정값이 소수점 일곱째 자리까지 일치한다(0.0244907 / 0.0244907). 크기가 1.46 배
차이 나는 두 지점에서 같은 상수가 나왔으므로 비례 관계로 본다.

16:9 높이 기준으로 바꾸면 `글자 = 16:9 높이 × 0.043540` 이다.

### 3. 데스크톱 모드는 서로 닮음이다

컨테이너가 플레이어 전체이고, 배치가 백분율이고, 글자가 너비에 비례하므로 일반 · 극장 ·
전체화면은 **크기만 다르고 모양이 같다.** 정규화한 캔버스에 그리면 세 모드의 결과 이미지는
구분되지 않는다. 세 모드를 나누는 실익은 절대 픽셀 크기가 영향을 주는 곳
(가독성 경고, 글자 크기 하한, 세이프 에어리어 판정)에 있다.

### 4. 우리 렌더러와의 차이

현재 `SubtitleLayoutEngine` 은 이렇게 계산한다.

```
viewportScale = SubtitleSpace.Height / 720
글자 크기 = 32 × viewportScale × (SizePercent / 100) × FontScaleBase
```

즉 **자막 공간의 높이**를 기준으로 삼는다. 유튜브는 **플레이어 너비**를 기준으로 삼는다.

- 16:9 에서는 높이와 너비가 비례하므로 두 기준이 같은 결과를 낸다.
  기본 배율끼리 비교하면 32/720 = 0.044444 대 0.043540 으로 우리 쪽이 약 2.1% 크다.
- 16:9 가 아닌 자막 공간에서는 어긋난다. 모바일 세로(9:16)에서 자막 공간을 세로 화면
  전체로 잡으면 우리 렌더러는 높이 기준이라 글자가 과도하게 커진다.

따라서 모드를 도입할 때 글자 크기 기준을 너비로 옮기거나, 모드마다 16:9 기준 높이를
`SubtitleSpace` 로 넘겨야 한다.

## 측정하지 못한 것

정직하게 남긴다. 아래는 이 문서에 확정값이 없다.

- **전체화면**: 브라우저 자동화에서 전체화면 전환이 사용자 제스처 제한에 걸려 측정하지
  못했다. 규칙 2와 3이 1.46 배 크기 차이에서 성립했으므로 화면 크기(예: 1920 × 1080)에
  같은 규칙을 적용하는 것은 외삽이다. 실측으로 확인이 필요하다.
- **모바일 세로**: 디바이스 에뮬레이션을 시도했으나 도구가 반복해서 죽어 측정하지 못했다.
  세로 컨테이너 안에서 자막이 영상 영역에 붙는지 화면 전체에 붙는지가 핵심 미지수이고,
  이 값이 규칙 4의 처리 방식을 정한다. **추정하지 않는다.**
- **레터박스 조합**: 4:3 영상을 16:9 플레이어에 넣은 경우만 보았다. 21:9 처럼 세로로
  레터박스가 생기는 조합에서 컨테이너가 영상 영역으로 줄어드는지 확인하지 못했다.
