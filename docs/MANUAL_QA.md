# MANUAL_QA.md

> **문서 기준:** v0.2.5 (2026-08-30)

## v0.2.5 YouTube 재생 준비 회귀 QA

v0.2.4까지는 Deno 자동 설치가 다운로드 직후 SHA-256 검증 단계에서 자기 자신의 파일 핸들과 충돌해 항상 실패했고, 구버전 yt-dlp가 이미 설치된 환경에서는 `--js-runtimes` 미지원으로 사전 확인이 즉시 실패했다. 릴리스 후보에서는 다음을 확인한다. (1) Deno가 없는 환경에서 YouTube 주소 열기가 다운로드·해시 검증·압축 해제·설치까지 끝나는지, (2) `--js-runtimes`를 지원하지 않는 오래된 yt-dlp가 `PATH`에 있을 때 고정 공식 자산으로 대체되어 재생이 되는지, (3) 이전 실패로 남은 `.deno-install-*` 임시 폴더가 다음 설치에서 정리되는지, (4) 두 번째 실행이 네트워크 없이 기존 설치본을 재사용하는지 확인한다.

Windows x64는 2026-08-30 실측으로 (1)(2)(4)를 통과했다. macOS arm64 / Linux x64는 미실측이다.

## v0.2.3 영상 엔진 자동 설치 QA

릴리스 후보에서는 Windows x64, macOS arm64, Linux x64 각각 깨끗한 사용자 환경에서 다음을 확인한다. (1) libmpv가 없는 상태에서도 영상/YouTube 열기 명령이 활성화되어 있는지, (2) 첫 영상 열기에서 다운로드·해시 검증·압축 해제·사용자 영역 설치가 완료되는지, (3) 같은 요청이 설치 직후 실제 재생으로 이어지는지, (4) 두 번째 실행은 네트워크 없이 기존 설치본을 재사용하는지, (5) 설정에서 재설치/수동 경로 지정 후 재생 소스가 정상 재초기화되는지 확인한다. YouTube는 yt-dlp 미설치 상태도 별도로 반복한다.

자동화할 수 없는 검증 항목. 대부분 실제 유튜브 업로드가 필요한 `[EMPIRICAL]` 작업이다.
수행하면 결과를 `docs/YTT-VERIFICATION.md`에 반영하고 체크박스를 켠다.

**증거 없이 체크하지 마라.** 스크린샷·영상 링크·측정 수치를 남긴다.

## YouTube 주소 스트리밍 (이슈 #26)

아래 항목은 공개 YouTube VOD를 네트워크로 재생하는 수동 확인이다. 수행 전 주소,
`yt-dlp` 버전, 운영체제, 앱 버전과 결과 화면을 기록한다. 체크하기 전에는 모두
미검증으로 둔다.

### 사전 준비

1. 자막 cue가 두 개 이상 있는 `.ytt` 또는 `.ass`를 준비하고, 캔버스에 표시될 cue의
   시작·끝 시각과 개수를 기록한다.
2. `yt-dlp`를 앱 실행 파일과 같은 디렉터리에 두거나 `PATH`에 설치한다. 앱 디렉터리와
   `PATH` 중 실제로 사용한 위치와 `yt-dlp --version` 결과를 기록한다.
3. 재생 가능한 공개 VOD의 `https://www.youtube.com/watch?v=...` 주소와
   `https://youtu.be/...` 주소를 각각 준비한다. 실험 당시 공개 상태와 주소를 기록한다.
4. 테스트 전 앱 디렉터리와 지정한 다운로드 폴더의 파일 목록을 기록한다. 이 기능은
   영상 파일을 내려받지 않으므로 테스트 뒤 영상 파일이 새로 생기지 않아야 한다.

### 정상 watch / youtu.be 주소

- [ ] 도구 모음에서 **주소로 열기**를 누른다. 같은 명령이 `파일 → 주소로 열기`에도
      있는지 확인하고, 주소 입력 창이 열리는지 기록한다.
- [ ] `watch?v=...` 주소를 입력해 확인한다. 메타데이터가 표시되고 첫 프레임에서 멈춘
      상태로 열리는지, 앱이 종료되지 않는지 확인한다.
- [ ] `youtu.be/...` 주소도 같은 절차로 연다. 두 형식 모두 동일한 영상이면 같은
      콘텐츠가 열리는지 확인한다.
- [ ] 재생·정지를 반복하고, 위치 슬라이더와 타임라인을 탐색하고, 프레임 앞·뒤 이동,
      0.5x·2x 속도, 볼륨 조절·음소거를 각각 확인한다. 동작이 로컬 파일과 같은지
      기록하되 네트워크 지연은 별도로 적는다.
- [ ] 주소 영상이 재생되는 동안 현재 cue를 캔버스에서 끌어 옮긴다. 위치가 바뀌고
      자막이 계속 영상 위에 합성되는지 확인한다.
- [ ] 선택 상자의 **왼쪽 위·위쪽 가운데·오른쪽 위·왼쪽 가운데·오른쪽 가운데·
      왼쪽 아래·아래쪽 가운데·오른쪽 아래** 조절점을 각각 끈다. 맞은편 점 또는 변이
      고정되고, 자막 크기가 비율을 유지한 채 바뀌는지 확인한다.
- [ ] 타임라인에서 cue 몸통을 끌어 전체 구간을 이동하고, 왼쪽 끝을 끌어 시작 시각을
      바꾸고, 오른쪽 끝을 끌어 끝 시각을 바꾼다. 캔버스 표시와 시작·끝 값이 각각
      갱신되는지 확인한다.
- [ ] 테스트 전후 파일 목록을 비교해 영상 파일이 앱 디렉터리나 다운로드 폴더에
      생기지 않았는지 확인한다. 스트림 데이터는 네트워크로만 받는 경로여야 한다.

### 실패 사유를 구분하는 확인

- [ ] **주소 형식 오류:** `not-a-url`과 YouTube가 아닌 `https://example.com/video`를
      입력한다. 네트워크를 시도하기 전에 주소 형식 오류로 안내되고, 앱과 현재 문서가
      살아 있는지 확인한다.
- [ ] **yt-dlp 없음:** 별도 테스트 프로세스에서 앱 디렉터리의 실행 파일을 잠시 다른
      이름으로 바꾸고 `PATH`에서도 `yt-dlp`를 제거한 뒤, 정상 VOD 주소를 입력한다.
      yt-dlp 없음으로 안내되는지 확인한다. 앱이 종료되지 않고, 복구 후 로컬 영상은
      계속 열리는지 확인한다. 테스트가 끝나면 실행 파일 이름과 `PATH`를 복원한다.
- [ ] **네트워크 실패:** 정상 VOD 주소를 준비한 뒤 테스트 기기의 네트워크 또는 해당
      연결을 일시적으로 차단하고 주소를 연다. 주소 형식 오류나 yt-dlp 없음이 아니라
      네트워크 실패로 안내되는지, 앱이 멈추거나 종료되지 않는지 확인한다. 네트워크를
      복구한 뒤 같은 주소를 다시 열고 로컬 영상도 확인한다.
- [ ] **재생할 수 없는 영상:** 확인 가능한 테스트 자료를 사용해 생방송, 연령 제한,
      비공개, 지역 차단 영상을 각각 시도한다. 주소 형식은 맞지만 재생할 수 없는
      영상으로 안내되는지와 각 시도 후 앱이 계속 살아 있는지를 확인한다. 계정·지역에
      따라 결과가 달라질 수 있으므로 사용한 주소와 조건을 증거에 남긴다.

### rapid scrub, URL 재로드와 안정성

- [ ] 정상 VOD가 열린 상태에서 위치 슬라이더와 타임라인을 10초 이상 빠르게 끈다.
      70ms보다 짧은 입력이 쏟아져도 탐색 요청이 모두 전송되지 않고, 마지막 위치가
      우선되는지 확인한다.
- [ ] 드래그를 멈춘 뒤 실제 재생 위치가 마지막 포인터 위치에 도달하는지 확인한다.
      중간 위치에 멈추거나 예외·화면 멎음이 있으면 입력 속도, 마지막 위치, 로그를
      기록한다.
- [ ] URL A를 연 뒤 URL B를 열고 다시 URL A를 연다. 각 로드가 이전 영상의 프레임이나
      메타데이터를 잘못 남기지 않고, 정지·재생·탐색이 새 영상에 적용되는지 확인한다.
- [ ] URL을 연 상태에서 앱을 정상 종료하고 다시 시작한다. 종료가 지연되거나 프로세스가
      남지 않는지, 다시 시작한 뒤 로컬 영상과 자막을 열 수 있는지 확인한다. 각 단계에서
      크래시·무한 대기·영상 파일 생성 여부를 기록한다.

## M5 캔버스 편집 및 undo/redo

- [ ] 영상 또는 자막을 연 뒤 미리보기의 빈 영역을 더블클릭하면 현재 시각부터 2초 cue가 클릭 위치에 생성되고 인라인 입력 상자가 열림
- [ ] 새 cue가 선택된 상태에서 텍스트를 입력하고 `Enter` 또는 바깥 클릭으로 확정하면 cue 내용이 갱신됨 (`적용` 버튼은 표시되지 않음)
- [ ] 빈 영역을 한 번 클릭하고 드래그하면 기존 범위 선택이 동작하며, cue를 드래그하면 위치 이동이 동작함
- [ ] 기존 cue 더블클릭은 새 cue를 추가하지 않고 해당 cue 텍스트만 인라인 편집함
- [ ] 새 cue 생성과 위치 지정 후 `Ctrl+Z` 한 번으로 cue가 함께 제거되고, `Ctrl+Y` 또는 `Ctrl+Shift+Z`로 동일한 cue가 복원됨
- [ ] 텍스트 상자에 포커스를 둔 상태에서 `Ctrl+Z`/`Ctrl+Y`는 창 명령이 아니라 텍스트 입력 기록을 되돌림/복원함
- [ ] 실행 취소 또는 다시 실행할 항목이 없을 때 단축키가 입력을 소비하지 않음

### 프리뷰 인라인 편집 절차 — 수동 검증 필요

GUI 자동화로 확인할 수 없는 항목이다. 아래 절차는 모두 **수동 검증 필요** 상태이며, 실제로 수행하기 전에는 체크하지 않는다. 수행할 때는 사용한 파일, 화면 크기, 운영체제, 스크린샷을 함께 남긴다.

#### 사전 준비

1. cue가 하나 이상 있는 `.ytt` 또는 `.ass` 파일을 열고, 원본 cue의 텍스트와 개수를 기록한다. 영상은 선택 사항이며, libmpv가 없어도 단색/체커보드 프리뷰로 절차를 수행할 수 있다.
2. 프리뷰 캔버스가 보이는 상태에서 테스트한다. 배치 클램프 절차에서는 cue를 프리뷰의 각 모서리와 가장자리에 가깝게 옮긴다.

#### 시작·확정·줄바꿈

- [ ] cue를 정확히 하나 선택하고 프리뷰 캔버스에 포커스를 둔 뒤 `F2`를 누르면 해당 cue의 인라인 입력 상자가 열린다. 편집을 끝낸 뒤 같은 조건에서 `Enter`를 눌러도 열린다. cue를 여러 개 선택했거나 선택하지 않은 상태에서는 이 시작 동작이 실행되지 않는지도 확인한다.
- [ ] 인라인 입력 중 문자를 한 글자씩 입력하고 프리뷰 자막 이미지가 입력 중인 텍스트로 즉시 바뀌는지 확인한다.
- [ ] 입력 중 `Shift+Enter`를 누르면 편집이 끝나지 않고 줄바꿈이 생기는지 확인한다. 이어서 `Enter`를 누르면 편집이 커밋되고 줄바꿈이 보존되는지 확인한다.
- [ ] 인라인 편집기에 `적용` 버튼이 표시되지 않는지 확인한다. `Enter` 또는 바깥 클릭으로 같은 텍스트가 커밋되는지 확인한다.
- [ ] 편집 중 입력 상자 밖의 프리뷰 영역이나 다른 패널을 클릭해 포커스를 잃게 했을 때 텍스트가 커밋되는지 확인한다.

#### 취소와 undo/redo

- [ ] 기존 cue의 텍스트를 기록한 뒤 인라인 편집을 시작하고 다른 텍스트를 입력한다. `Esc`를 누르면 원본 텍스트로 돌아가며 편집 내용이 undo 기록에 남지 않는지 확인한다. 이전에 만든 별도 undo 작업이 있다면 `Ctrl+Z`가 취소한 타이핑이 아니라 그 작업만 되돌리는지 함께 확인한다.
- [ ] 빈 프리뷰 영역을 더블클릭해 새 cue를 만들고 텍스트를 입력한다. `Esc`를 누르면 새 cue의 추가 자체가 취소되어 cue 개수가 원래대로 돌아가는지 확인한다. 취소된 입력/추가가 별도 undo 항목으로 남지 않는지도 확인한다.
- [ ] 기존 cue를 편집해 커밋한 뒤 `Ctrl+Z`를 **한 번만** 누른다. 글자 단위가 아니라 편집 세션 전체가 편집 전 텍스트로 되돌아가는지, `Ctrl+Y` 또는 `Ctrl+Shift+Z`로 세션 전체가 다시 적용되는지 확인한다.
- [ ] 새 cue를 만든 뒤 커밋한 경우에는 `Ctrl+Z` 한 번으로 텍스트와 위치를 포함한 cue 추가가 제거되고, `Ctrl+Y` 또는 `Ctrl+Shift+Z`로 같은 cue가 복원되는지 확인한다.

#### 입력 상자 배치와 단축키 회귀

- [ ] cue를 프리뷰의 왼쪽 위·오른쪽 위·왼쪽 아래·오른쪽 아래에 가깝게 배치하고 각각 인라인 편집을 시작한다. 입력 상자가 `Border` 안쪽 프리뷰 영역을 벗어나거나 잘리지 않는지 확인한다.
- [ ] 인라인 편집 중 `Space`가 재생/일시정지 단축키로 새지 않고 텍스트 입력으로 들어가는지 확인한다. 텍스트 상자에 포커스가 있을 때 `Ctrl+Z`/`Ctrl+Y`가 문서 명령이 아니라 텍스트 상자의 기본 undo/redo로 동작하는지도 확인한다.

### 프리뷰 WYSIWYG·크기 조절·큐 삭제 절차 — 수동 검증 필요

아래 GUI 항목은 자동 검증 결과로 체크하지 않는다. 실제로 수행하기 전에는 모두 **수동 검증
필요**로 취급하고, 수행했다면 파일·화면 크기·운영체제·스크린샷을
증거로 남긴다.

1. 폰트 패밀리, 폰트 크기, 전경색/불투명도, `Justification` 및 여러 줄 cue를 준비한다. 인라인
   편집을 시작해 실제 자막과 TextBox의 글자 모양·정렬·줄바꿈이 프리뷰 배율에서도 일치하는지
   확인하고, 프리뷰 창/캔버스 크기를 바꾼 뒤에도 두 표현의 배율이 계속 동기화되는지 확인한다.
   입력 중 한글과 일본어 IME를 조합해 조합 중인 글자까지 즉시 보이는지 확인한다.
2. 인라인 편집 중인 cue가 `SubtitleImage` 래스터에서 빠져 같은 글자가 두 번 겹쳐 보이지 않는지,
   나머지 cue는 계속 렌더되는지 확인한다.
3. 선택 박스 바깥 조절점 **여덟 개를 각각** 드래그한다. 잡은 점의 **맞은편 점(또는 변)이
   화면에서 움직이지 않고** 끄는 방향으로만 박스가 자라는지 확인한다. 오른쪽 가운데 점을
   끌면 왼쪽 변이, 왼쪽 위 모서리를 끌면 오른쪽 아래 모서리가 제자리인지 각각 확인한다.
   고정변과 나란한 방향으로만 움직였을 때 크기가 그대로인지도 확인한다. 박스 가로·세로를
   각각 다르게 늘이는 대신 `SizePercent` 배율만 바뀌어 가로세로 비율이 유지되는지,
   앵커 종류(`ap`)는 바뀌지 않는지 확인한다. `Shift` 드래그의 정밀
   조절, 여러 cue 선택 시 동일 배율 적용, 최소·최대 클램프를 확인한다. 위치 드래그에서 `Alt`
   스냅 해제가 계속 동작하며 리사이즈를 자유 스케일로 바꾸지 않는지도 확인한다.
3-1. 같은 조절점을 **끌지 않고 그냥 클릭**하면 크기가 그대로이고 그 점이 앵커가 되는지
   확인한다. 아주 조금(수 px) 흔들리게 눌렀다 뗀 경우에도 크기가 바뀌지 않고 앵커 선택으로
   처리되는지 확인한다. 가운데 원형 점은 드래그해도 크기가 바뀌지 않고 앵커만 바뀌는지
   확인한다.
4. 인라인 편집 TextBox에서 YTT 엣지·그림자·외곽선, 여러 section 혼합 스타일, 가라오케 음절
   단위 스타일이 정확히 재현되지 않는 문서화된 한계를 확인하고, 차이를 증거에 기록한다.
4-1. 프리뷰 캔버스에 포커스를 두고 cue를 선택한 뒤 `Delete`를 누르면 선택 cue가 삭제되는지
   확인한다. 인라인 편집 중에는 `Delete`가 cue를 지우지 않고 문자만 지우는지 확인한다.
5. 큐 목록의 행 자체에 포커스를 두고 `Delete`를 누르면 선택 cue가 삭제되는지 확인한다. 삭제
   뒤 이웃 행 선택과 목록이 빈 경우 선택 해제를 확인한다. 시작·끝 시각, Track, 텍스트 행의
   TextBox에 포커스를 둔 채 `Delete`를 눌렀을 때 문자만 지워지고 cue가 삭제되지 않는지 확인한다.
   인라인 편집 중에도 같은 포커스 가드가 유지되는지 확인한다.
